# 🍀 已有落地的 AI 开发实践

**先看 CodeRabbit。其余五项可以等遇到对应问题时再读。**

这里收录六种已经有真实使用记录的开发流程：CodeRabbit 审查 PR，以及 Issue 委派、故障诊断、安全修复、测试增强和版本迁移。每篇都有案例来源、工作流程，以及一个能停下来的小实验。

“已有落地”表示有公开 PR、具名使用者的实践记录，或描述实际部署的论文。它说明这条路径有人走通；个人项目的收益还要看任务、代码和验收条件。本仓库当前收录的是资料与实验建议，尚未接入这些服务。

资料核对：2026-10-22。案例不限于近期发布，具体时间在各篇标明。

如果想直接改善自己的日常开发，先看单独的[工作流分析：减少验收与返工](your-workflow.md)。它结合你的项目记录，说明哪些已落地做法最值得先试。

## 六种实践，按问题挑一个

| 想解决的问题 | 实践与入口 | 落地证据 |
| --- | --- | --- |
| PR 多了，想多一轮检查 | [CodeRabbit 自动审查 PR](01-coderabbit-review.md) | Nuxt 的公开 PR 有机器人审查记录；Cresta 有具名团队使用案例 |
| 问题清楚了，希望 AI 先完成实现 | [GitHub Copilot 从 Issue 到 PR](02-issue-to-pr.md) | GitHub Secret Protection 团队报告了经测试、人工审查并部署的代码 |
| 用户遇到错误，却很难在本地复现 | [Sentry Seer 从错误现场到修复](03-error-to-fix.md) | 独立开发者公开记录了 Seer 与 Cursor 协作生成并合并 PR 的过程 |
| 扫描发现漏洞，修复积压 | [CodeQL 与 Copilot Autofix](04-security-autofix.md) | GitHub 公布了真实 PR 告警的修复使用数据 |
| 想补测试，但担心生成无效断言 | [Meta TestGen-LLM 筛选有用测试](05-test-generation.md) | 论文记录了 Facebook、Instagram 的实际部署与工程师采纳结果 |
| 升级语言或框架，关联改动太多 | [Amazon Q 执行有界版本迁移](06-code-migration.md) | AWS 报告了生产 Java 应用的批量迁移 |

各篇“为什么收录”附有直接来源。公开操作记录、公司自述与论文中的部署报告，分别按原本的证据类型标注。

## 和头脑风暴怎样搭配

[构想地图](../issue-garden/04-ideas-map.md)继续保存想法与组合方式；这里保存已有实践的具体依据。Issue 委派和故障驱动原本就在地图中，现在也有了对应的案例页。

可以把几项实践接成一条流程：

```text
Issue 或错误记录 → AI 提出改动 → 测试与扫描 → AI review → 人验收
```

这是供本项目尝试的组合建议。不同案例的成功结果不能直接相加为整条自动化流程的成功率。

## 今天做到哪里就可以停

打开 [CodeRabbit 篇的公开 PR](01-coderabbit-review.md)，选一条审查意见，找到对应代码，判断它指出的问题能否复现。读懂一条就够了，今天不需要开通服务。

以后亲手试某个方案时，留下任务链接、代码版本、实际检查结果和自己的判断。出现过一次成功后，再观察多次任务中的误报、返修与验收耗时。
