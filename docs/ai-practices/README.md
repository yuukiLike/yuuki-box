# 让 AI 接手开发：挑一件真活试试

PR 刚写完，想找个搭档挑刺；错误堆栈攒了一屏，想有人陪你追到根因；版本该升了，关联改动却让人迟迟不想开工。就从其中一件事开始，把 AI 拉进一次完整的开发任务。

这里收录六种有公开使用记录的实践。每篇先给你一个具体场景，再看别人怎样做过，最后留一个可以亲手试的挑战。**带走一条经得起核实的意见、一份能解释的 diff，或者一条真能抓住 bug 的测试，就有收获。**

想先减少自己来回盯结果的次数，直达[你的工作流](your-workflow.md)。想跟着搭流程，去 [Issue 夜班](../issue-garden/README.md)；想自己写 Agent，去 [Agent 工程实验](../agent-engineering/README.md)。

“已落地”表示能找到公开 PR、具体团队或使用者的实践记录，或描述实际部署的论文。这说明有人在真实工作中用过，效果仍取决于任务、代码和验收条件。本仓库目前保存资料与实验建议，尚未配置这些自动化流程。

资料核对：2026-10-22。案例不限于近期发布，具体时间在各篇标明。

## 和构想怎样搭配

[构想地图](../ai-ideas/01-ideas-map.md)保存想法与组合方式，这里补充实际案例。例如“把 Issue 交给 AI”和“让错误记录发起修复”，都可以在上表找到对应流程。

可以把几项实践接成一条流程：

```text
Issue 或错误记录 → AI 提出改动 → 测试与扫描 → AI 审查 → 人验收
```

这条组合流程仍待本项目验证；各环节的实际案例不能代替整条流程的验收。

## 今天就开一局

手边有 bug，就用[工作流里的小实验](your-workflow.md#下一次只试一件事)追一次“复现 → 修复 → 同条件检查”。手边还没任务，就从 [CodeRabbit 篇](01-coderabbit-review.md)打开公开 PR，挑一条审查意见，自己判断它成立不成立。无需先安装任何服务。

以后亲手试某个方案时，留下任务链接、代码版本、实际检查结果和自己的判断。再用后续任务观察误报、返工与验收耗时，不急着从一次成功下结论。
