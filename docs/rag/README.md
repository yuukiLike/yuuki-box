# RAG：先找资料，再回答

RAG（检索增强生成）把相关资料放进模型上下文，再生成回答。<mark class="key">先检索，再回答，并保留出处</mark>。

```text
资料 → 分块 → 检索片段
问题 + 片段 → 模型回答（带出处）
```

本例使用虚构笔记产品的三份规则。Node.js ≥22.22，无需安装依赖；本地脚本完成检索和提示构造，生成在现有 Codex 或聊天模型中完成。

## 1. 检索本地资料

在仓库根目录运行：

```bash
pnpm demo:rag
```

输出应包含：

```text
[本地检索] 命中 1 段；尚未调用模型。

[交给模型]
```

其后的提示包含问题与资料：

```text
问题：阅读进度保存在哪里？

资料：
[reading.txt#1]
阅读进度保存在当前浏览器的 localStorage。
```

`reading.txt#1` 表示文件与片段编号，可回到[原文](labs/knowledge/reading.txt)核对。

## 2. 交给模型回答

复制终端中 `[交给模型]` 后的完整提示，发送到现有 Codex 会话或聊天模型。

模型应根据资料回答，例如：

```text
阅读进度保存在当前浏览器的 localStorage。[reading.txt#1]
```

核对事实与引用都来自检索片段。<mark class="key">模型生成发生在这一步</mark>；本地脚本不联网，所选模型按自身的额度与规则运行。

## 3. 核对资料不足

换一个资料中没有的问题：

```bash
pnpm demo:rag "退款多久到账？"
```

预期：

```text
资料不足：没有匹配片段。
```

没有命中时不构造生成提示；有命中也只表示关键词相近，不能据此认定资料足以回答。

## 最少代码

实现：[rag.mjs](labs/rag.mjs)。

| 部分 | 职责 |
| --- | --- |
| `loadDocuments` | 读取三份 `.txt` 规则 |
| `retrieve` | 按段分块、中文分词、按命中词数排序，最多返回两段，每段最多 300 字符 |
| `buildPrompt` | 合并问题、片段与引用要求；空结果返回 `null` |

修改[资料目录](labs/knowledge/)后重跑，可观察回答依据随资料变化；资料随提示进入模型上下文，模型参数保持不变。
