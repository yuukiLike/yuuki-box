# RAG：先找资料，再回答

**RAG** 是 **Retrieval-Augmented Generation** 的缩写，中文为**检索增强生成**。做法是<mark class="key">检索相关资料，补充到模型上下文，再生成回答</mark>。

## 什么时候需要 RAG

模型的训练语料有时间边界，也未必包含内部文档。政策刚更新时，模型可能仍按旧规则回答；RAG 可以在提问时检索当前生效的原文，补充回答依据。

常见用途：政策与收费规则查询、内部手册问答、需要出处的产品咨询。

```text
准备：资料 → 分块并保留来源

问题 → 检索相关片段
问题 + 片段 → 模型 → 带出处的回答
```

下面用一条**虚构的产品政策**演示：导出文件可下载 14 天。两节依次完成查询、更新与核对。

需 Node.js ≥22.22 与 pnpm。本地脚本无额外依赖，负责检索和构造提示；回答由现有 Codex 或聊天模型生成。

## 1. 检索本地资料

在仓库根目录运行：

```bash
pnpm demo:rag "导出文件可下载几天？"
```

输出中的政策片段：

```text
[policy.txt#1]
演示笔记产品的导出保留政策（虚构）：版本 v1；生效日期 2026-11-01；导出文件可下载14天。
```

`policy.txt#1` 表示文件与片段编号，可与[政策原文](labs/knowledge/policy.txt)核对。终端还会列出其他匹配片段。

## 2. 交给模型回答

复制终端中 `[交给模型]` 后的完整提示，发送到现有 Codex 会话或聊天模型。

模型应根据资料回答，例如：

```text
按 v1（2026-11-01 生效），导出文件可下载 14 天。[policy.txt#1]
```

核对天数、版本和出处是否与原文一致。<mark class="key">检索提供依据，模型组织回答</mark>；仅有引用标记，不能证明结论正确。

## 3. 核对资料不足

换一个资料中没有的问题：

```bash
pnpm demo:rag "退款多久到账？"
```

预期：

```text
资料不足：没有匹配片段。
```

没有命中时脚本停止，不构造生成提示；命中片段无法回答问题时，提示也要求模型报告“资料不足”。

## 最少代码

实现：[rag.mjs](labs/rag.mjs)。本例按关键词检索，使用三个函数：

| 部分 | 职责 |
| --- | --- |
| `loadDocuments` | 读取本地 `.txt` 资料 |
| `retrieve` | 按段分块、中文分词、按命中词数排序，最多返回两段，每段最多 300 字符 |
| `buildPrompt` | 合并问题、片段与引用要求；空结果返回 `null` |

资料随提示进入本次上下文；<mark class="key">RAG 不修改模型参数</mark>。

<details>
<summary>选读：检查脚本</summary>

```bash
pnpm check:rag
```

检查中文检索、资料不足、引用、片段限制与资料更新；模型回答需在第二步核对。

</details>
