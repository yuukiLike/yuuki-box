# RAG：更新资料与核对时效

政策、收费或产品规则更新后，模型可能仍保留旧知识。先更新检索资料，再让模型依据新版本回答。

本章沿用虚构笔记产品，演示导出文件的保留期限变化。

## 1. 查询现有规则

```bash
pnpm demo:rag "导出文件可下载几天？"
```

首个片段应为 `policy.txt#1`，含 `v1`、生效日期 `2026-11-01` 与 `14天`。完整提示交给模型后，核对回答及引用。

## 2. 更新资料，重新提问

将 [policy.txt](labs/knowledge/policy.txt) 改为：

```text
演示笔记产品的导出保留政策（虚构）
版本 v2；生效日期 2026-11-02
导出文件可下载7天。
```

重跑同一命令，把新提示交给模型。现在依据应是 `v2`、`2026-11-02` 与 `7天`。

<mark class="key">改变的是检索资料与本次上下文，模型参数保持不变</mark>。本例每次读取本地文件；正式系统还需同步权威原文、更新索引，再提供检索。同步可由定时任务或发布事件触发。

## 3. 核对时效

- **来源：** 采用发布机构或资料所有者的原文，保留出处与版本。
- **日期：** 分别核对发布、生效及问题所指日期，结合适用范围选版本。
- **更新：** 按资料变化频率刷新；旧版本退出当前检索并留档，历史问题检索对应版本。

资料源未刷新时，RAG 仍可能引用旧政策；命中内容不足以支持答案时，应报告“资料不足”。

## 下一步：工具接入

需要让模型自行触发检索时，可把 `retrieve` 封装为查询工具；接入方式见[MCP 服务](../ai-from-scaling/00-codex-mcp.md)。资料规模增长后，再选读语义检索与向量索引。
