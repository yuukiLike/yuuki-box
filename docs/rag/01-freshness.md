# RAG：更新资料与核对时效

沿用上一节的虚构政策，将导出文件的下载期限从 **14 天改为 7 天**。<mark class="key">RAG 的时效取决于资料是否及时更新</mark>。

## 1. 查询现有规则

```bash
pnpm demo:rag "导出文件可下载几天？"
```

首个片段应为 `policy.txt#1`，含 `v1`、生效日期 `2026-11-01` 与 `14天`。

## 2. 更新资料，重新提问

将 [policy.txt](labs/knowledge/policy.txt) 改为：

```text
演示笔记产品的导出保留政策（虚构）
版本 v2；生效日期 2026-11-02
导出文件可下载7天。
```

重跑同一命令，把 `[交给模型]` 后的完整提示发送到模型。预期回答类似：

```text
按 v2（2026-11-02 生效），导出文件可下载 7 天。[policy.txt#1]
```

本例由人工确认新规则已生效，再更新文件；脚本每次重新读取资料，不自动判断日期。正式系统可用定时任务或发布事件同步原文，并更新检索索引。

## 3. 核对时效

- **来源：** 使用发布机构或资料所有者的原文，保留出处与版本。
- **日期：** 发布不等于生效；按问题所指日期与适用范围选版本。
- **更新：** 旧版退出当前检索并留档；询问历史规则时，使用对应版本。

若仍回答 14 天，先看检索片段：命中旧版就检查资料与索引是否刷新；片段已是新版，就检查模型回答是否遵循依据。

## 下一步：换成实际资料

1. 用实际政策或手册替换[资料目录](labs/knowledge/)中的示例 `.txt`。用空行分段，每段不超过 300 字符，并附来源与生效日期。
2. 分别用原话、同义问法和资料外问题查询，记录 **问题 / 命中片段 / 回答 / 引用**；无依据时应报告“资料不足”。
3. 更新一条规则后重新提问，核对当前回答采用新版本。

关键词经常漏掉同义表达时，可加入 **embedding（文本向量）语义检索**；资料规模增大后，再考虑向量索引。先验证资料能被找对、引用能支持回答。
