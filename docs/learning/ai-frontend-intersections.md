# AI 与前端还可以在哪些地方相遇

把已有的渲染、语音与 Agent 资料放在一起，可以看到几条连续的学习路线。每条路线都从一个前端问题开始，以一个能观察的小实验收束。

## 几条可选的路线

| 前端的问题 | AI 里的对应问题 | 下一次可以做的小实验 | 入口 |
| --- | --- | --- | --- |
| 每次都查找或重算，能否复用 | KV 与跨请求前缀缓存 | 改一个依赖，看复用范围怎样变化 | [前端缓存](../frontend-foundations/README.md)、[KV 专题](../kv-cache/README.md) |
| 计算太久，输入和取消跟不上 | Worker 中的预处理或推理 | 一项固定计算放进 Worker，观察取消与过期结果 | [Wasm](../wasm/README.md)、[已有 Worker](../../examples/react-webview/src/lab-worker.js) |
| 网络很快，界面却卡顿 | 流式模型输出与 UI 消费速度不同 | 同一段文本按不同批次发布，观察解析次数 | [渲染与流式输出](rendering-performance.md) |
| 语音什么时候算说完 | VAD、转写分段与草稿状态 | 先检测人声区间，再把转写结果放入可编辑草稿 | [语音工具](../tts/README.md) |
| 本地资料如何按意思查找 | Embedding、向量相似度与检索上下文 | 固定几段文字，比较关键字和语义查询 | [浏览器 AI](../wasm/browser-ai.md) |
| 一个按钮的异步任务怎样可靠结束 | 工具循环、审批、取消与恢复 | 沿一次运行追踪受理、进度与终态 | [Agent 架构](../architecture/mac-local-harness.md) |

## 最适合现在新开的一条线

**先选 Wasm 与 Worker。** 已有前端 Worker 代码可以阅读，文档站也提供了一个真实 Wasm 调用。可以先复用现成计算模块，把数据、状态和取消走通，再考虑加载模型。

这条选择服务于当前的学习顺序：它直接连接 JavaScript、内存、异步任务和 AI 执行位置。第一轮能够形成清楚的输入输出，不依赖复杂的模型生成表现。

接下来值得组合的是流式文本渲染。模型越快，前端越需要知道哪些工作应批量执行、哪些结果能缓存，以及用户输入何时被处理。与 KV Cache 放在一起读，可以同时理解服务端省算和客户端省算。

## 把每个实验限制在一个问题内

一个实验先只改一个因素：

- 查找实验改数据量或目标位置，分别记录索引准备和查找工作。
- 缓存实验改内容、版本或容量，观察命中、失效与淘汰。
- Worker 实验改批次大小，观察吞吐、响应和取消机会。
- 浏览器 AI 实验区分首次初始化与同一实例的重复执行。

结果至少包含正确输出、实际做过的工作和资源生命周期。性能数字再附上设备、输入、构建方式与测量位置，才能用于比较。
