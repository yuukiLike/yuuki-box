## 语音：让输入和复习接起来

### 1 · 语音灵感箱：走两步，说清下一件事

想到问题、不想开编辑器时先录音。

```text
录一段话 → 转写为文字 → 整理成灵感卡 → 自己确认 → 保存
```

保存转写，再提取“问题、已知、缺失、下一步”；未说出的决定留空。

可以这样要求文本模型：

> 根据这段转写整理一张灵感卡。保留原话中的犹豫和未确定项，给出一个能在十分钟内验证的下一步，并引用对应原句。

录 3 段，核对术语、否定词、数字及整理是否忠实。文件先用 `gpt-transcribe`；麦克风流另走实时转写。[转写说明](https://developers.openai.com/api/docs/guides/speech-to-text)

### 2 · 有声笔记：把一篇文章变成能听的讲解

选有权处理的笔记，整理约 90 秒讲解稿，核对后合成声音。公式、代码、链接改成口述，文稿保留原文位置。

比较“讲给初学者”与“三个问题复习”，查概念、术语和停顿；保存文稿与音频，仅重生成改动段落。

`tts-1`、`tts-1-hd`、`gpt-4o-mini-tts` 已弃用，计划 2027-01-06 停用。新接入按指引改用 `gpt-realtime-2.1-mini` 与 Realtime API，不能只改模型名；对外标明 AI 合成。[迁移说明](https://developers.openai.com/api/docs/guides/text-to-speech)

本地入门见[让 Yuuki 开口说第一句话](../tts/让-Yuuki-开口说第一句话.md)；用同一文稿比较本地与云端声音。

### 3 · 口答复习：解释完，再接一个追问

提供一小节资料，每次问一题、语音作答，助手指出遗漏并追问；五轮后保存“回答、依据、缺口”。

如 KV Cache：先问“改前缀为何影响复用”，再问“只改末尾呢”；仅依据所给资料判答。

首版分开检查“录音 → 转写 → 判答 → 语音”。连续对话再选 GPT-Live（边听边说、后端任务）或 Realtime（语音回合、状态、工具）。[架构选择](https://developers.openai.com/api/docs/guides/audio)、[GPT-Live](https://developers.openai.com/api/docs/guides/live)、[Realtime](https://developers.openai.com/api/docs/guides/realtime)

查听取、打断与复习记录是否正确；结束时关闭会话、保存用量。浏览器由可信后端处理项目 Key，按 API 流程连接。[接入与结束会话](https://developers.openai.com/api/docs/guides/live)

## 音乐：从创作想法走到试听和画面

OpenAI 生成**编排、歌词、说明、配图与旁白**；音乐工具负责生成或渲染音频。

### 4 · 配乐草案：同一个场景，试听三个方向

为“雨夜读书的 Yuuki”设计钢琴、电子、室内乐三版；各列时长、速度、乐器、情绪与结尾，歌词另备。

> 给这个场景设计三份 30 秒配乐草案。每份列出乐器、节奏、前中后三段的变化和结尾。保留我给的场景细节，标出需要试听才能决定的部分。

按[ACE-Step 教程](../windows-local-ai/02-ace-step-music.md)固定其他参数、本地生成并试听。<mark class="caution">OpenAI 额度只支付前面的 API 请求</mark>；ACE-Step 用本地算力，其他服务另计费。未验证 OpenAI 专用歌曲生成接口。

**成果：** 三份配乐描述、试听文件与下一步修改记录。

### 5 · MIDI 讲解卡：让说明对应正在响的音符

沿用[钢琴排练台](../ai-from-scaling/07-music-space-mcp.md)，解析 MIDI 轨道、音高、起点和时值；给模型选定小节的数据，解释声部进入、休止与节奏，生成旁白。

```text
MIDI → 解析后的音符与小节 → 文字讲解 → 人工核对 → 旁白与可视化
```

定位两处小节、独听声部并核对说明；解析、播放与空间渲染留在本地，模型只讲解数据。

**成果：** 两张含小节、数据与试听入口的讲解卡。MP3/WAV 包络只控制画面起伏，准确音符与声部仍用 MIDI。

### 6 · 音乐照片短片：给一段音乐做一套视觉

选有权使用的音乐，生成场景、配色、运镜及封面。前中景另做透明图层，查尺寸、遮挡与风格，再交[舞台预演台](../ai-from-scaling/08-music-photo-mcp.md)导入导出。

```text
音乐与主题 → 分镜草案 → 背景 / 透明图层 → 音乐 MCP 时间轴 → MP4
```

先导出 4 秒，查可播放、运动与音画对齐。图片消耗 API；音乐播放、Three.js 与 FFmpeg 在本地执行，旁白另走语音合成。[图片生成与编辑](https://developers.openai.com/api/docs/guides/image-generation)

**成果：** 封面、可编辑图层与有声短片。

## 图片与日常：让生成结果可以找回、继续编辑

### 7 · 截图记忆库：问一句话，返回原图

20 张截图编号后，生成说明与可见文字，保存原图路径；查询“粉色侧栏设置页”时返回候选原图。

用五种说法查已知截图并核对命中；仅新增或换图时更新说明，索引可复用。来源与步骤见[截图记忆库](openai-api.md#community-ideas)。

### 8 · 学习漫画：同一个角色解释三个步骤

选“缓存命中 → 条件变化 → 失效”一个知识点；核对三格分镜后带参考图生成，漂移时单格编辑，公式代码后期排版。

检查知识、角色与因果，保存参考图、分镜、提示词和结果供续作。参考图可用作编辑输入。[图片工作流](https://developers.openai.com/api/docs/guides/image-generation)

## 给每轮实验留一个停点

先选一个方向，用上表的小样本完成一轮。为每份成果保留四项记录：

| 记录 | 方便以后判断什么 |
| --- | --- |
| 输入素材与提示词 | 换模型或调整要求时能否比较 |
| 原始返回与最终成果 | 哪部分来自模型，哪部分经过修改 |
| 模型、用量与实际费用 | 这一轮值不值得继续扩大 |
| 一条下一步 | 下次接着改哪里 |

在 [Usage](https://platform.openai.com/usage) 查用量，[Billing](https://platform.openai.com/settings/organization/billing/) 查余额与到期。赠额仅抵扣关联组织符合规则的 API，用完会继续扣购买余额。[赠额规则](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)。

先做 **3 张语音灵感卡**，完成后加语音回答；音乐方向走“配乐草案 → 本地试听 → 封面与 4 秒短片”。
