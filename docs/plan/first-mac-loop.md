# 第一轮 Mac 闭环开发计划

实现记录：2026-09-26。五路线已接入 Agent 与 Whisper，包含 DeepSeek、固定工具、审批、取消和持久会话；统一构建、打包、本地签名成功（build-all.sh 退出码 0）。当时未执行测试与 computer-use，<mark class="caution">未打开应用、调用 API、识别语音或测量性能</mark>，不代表后续也跳过验证。

使用与边界见 [AI 与语音基础](../architecture/ai-and-speech-foundation.md) 和 [runtime README](../../examples/shared/runtime/README.md)。下文是完整产品里程碑，实现与运行验收分开记录。

已确认自建模型/工具循环、先 Mac 后远程，并行体验 Swift、Rust/GPUI 与 React 宿主。最终 UI 和运行时语言未定，可直接从 GPUI/Rust 开始；SQLite 与独立 Runner 仍是建议。

相关文档：[五路线 examples 入口](../../examples/README.md) · [阅读入口](../README.md) · [产品架构调研](../research/zed-raycast-warp.md) · [Harness 提案](../architecture/mac-local-harness.md) · [渲染实验](../learning/rendering-performance.md)。

起始验证路径为“输入任务 → 收到事件 → 更新一行”；核对状态变化与停止信号的接收者，再扩展模型或工具。

## 1. 首轮交付目标

完整闭环应支持选择工作目录、提交任务、查看结构化进度、按策略授权、取消，以及重开后的可信记录。

逐步补齐模型失败、工具超时、大输出、取消竞态和中断后未知结果；模拟演示不等于完整 Harness。

体验目标：Agent 工作时，输入、滚动、切换和取消仍顺畅。

## 3. 已开始的第一项任务：五路线 Mac 窗口实验

五个免密钥回放演示已扩展 DeepSeek、工具循环、审批、持久会话和 runtime 子进程；使用 AI 时才配置密钥。Whisper CLI 与模型另备。

### 已实现的共同范围

1. 各有独立窗口与构建入口，可任选修改。
2. 共同 fixture 含 `message` / `tool`，扩展为 1,000/10,000 条独立 ID 历史，支持全部/工具筛选。
3. 回放每 50 ms 追加一条，每轮最多 200 条、总计最多 10,200 条，可开始/停止。
4. 更新清单覆盖有更新、当前版本和无效清单，仅发现版本、展示状态，未做安装/替换/重启。
5. 共用 Apple Speech/AVFoundation helper，默认设备端识别；用户启动后才申请权限与采集。

编译不代表交互、识别、性能或安装验收。侧栏尚非独立会话选择，固定 `tool` 行不执行系统工具；限制见各路线 README。

### M0 尚未完成的内容与以后可选的观察

当时未执行测试与 computer-use，以下均未验收；后续按改动选择检查：

- 追加事件、切换状态不丢输入。
- 会话输出按身份落位，不串到当前会话。
- 向上阅读不被强制拉到底部，提供返回最新入口。
- 异步 Runner 停止时先显示“正在停止”，终态只结束一次；固定回放目前仅演示定时追加与取消。
- 新增文本不重解析全部已完成历史。
- 性能比较记录环境、负载和一致优化构建；当前无基线，不把目标当实测。

详细采样方法、变量控制与测量表见[渲染性能学习与实验](../learning/rendering-performance.md)。

## 4. 从原型到完整闭环

按成果划分阶段，不承诺日历工期；可在任意路线推进或并行学习，实际耗时取决于学习、能力范围与模型接入。

| 阶段 | 交付物 | 验收重点 | 当前状态 |
|---|---|---|---|
| M0：环境与回放 | 五路线窗口、固定模拟事件流；后续可选采样 | 输入、真实会话切换、停止和长历史 | 已有源码与构建；新增会话 UI，交互与性能未验收 |
| M1：真实模型循环 | 一个模型提供方、结构化响应与用量 | 流式完成、错误、取消、结束原因 | DeepSeek SSE、用量和结束状态已实现；未付费调用 |
| M2：最少工具闭环 | 文件读取、搜索、修改与命令执行 | 参数校验、策略、工具结果回传、超时和输出上限 | 部分实现：列目录、读文件、审批后新建笔记；无 shell、覆盖或删除 |
| M3：可信记录与恢复 | 状态/事件持久化、产物与中断恢复 | 结果未知、重复提交、崩溃窗口与凭据处理 | 部分实现：原子 JSON、Keychain、导出与中断标记；无 SQLite/故障注入 |
| M4：独立 Runner 与性能收敛 | 独立生命周期、重连与代表性负载记录 | 退出语义、进程树、缓冲上限、空闲开销 | 已有随 App 退出的子进程；无后台常驻、重连或性能实测 |

前期保留持久化与 Runner 边界，先跑通循环，再验证退出后运行、崩溃恢复等性质。

### M1：一个模型提供方

先接一家提供方，保留消息、工具 schema、流式事件、结束原因、用量与原生附加数据，不预造多模型抽象。

区分请求失败、流中断、正常结束、输出上限与取消，不把错误伪装成功；可重试的错误需限制次数与时间。

接入时核实提供方、模型、认证及最新文档；本文不指定模型、价格、上下文或 API 参数。

验收：普通回答、工具结构解析、流中断、超时、取消及缺失/延迟用量。

### M2：工具形成闭环

首批工具围绕读文件、搜索、受控修改和命令执行；输入、输出、错误结构化，UI 不解析终端文字猜状态。

先顺序执行，独立读取确有需求再有限并发；并发写、子 Agent 和依赖调度后置。

运行前校验参数与策略；工作目录、环境、输出上限、超时和进程结束均写入契约。限定目录不等于 OS 沙箱，未隔离时需写明权限。

验收：成功、无效输入、权限拒绝、待授权时取消、命令失败/超时、大输出及模型处理结构化错误。

<div class="heading-alias" id="m3让记录可信" aria-hidden="true"></div>

### M3：状态持久化与恢复

<mark class="key">执行意图先落盘</mark>，结果返回后状态与事件一起提交。大输出存受限文件或产物，UI/模型按需读取。

恢复时区分未执行、已完成和未知；未知结果按工具能力检查或转人工，不一律重跑。

系统凭据库存密钥，数据库仅存引用与非敏感配置。保留供应商原生元数据，不声称采集模型内部推理。

验收：执行前/中/结果落盘前崩溃、重复提交、重启恢复显示和大日志保留/清理。

<div class="heading-alias" id="m4把生命周期与响应落实" aria-hidden="true"></div>

### M4：生命周期与响应性

分别定义关窗口、退出 App、停 Runner 和系统重启；能启动子进程不代表有独立可靠生命周期。

退出 UI 后继续工作需验证系统管理的 helper；若退出即停止，则明确提示并回收子进程。

用真实模型/工具重跑 M0，再测突发输出、慢 UI 与长期空闲。逐进程记录 CPU、内存和生命周期，不漏子进程。

## 5. 后续可选验证矩阵

下表在上述交付中均未验证；后续按阶段选择检查，源码存在不等于行为通过，也不必先搭完完整测试体系。

| 情况 | 预期行为 | 合适的验证方式 |
|---|---|---|
| 模型返回工具调用 | 调用校验后执行，结果关联原调用并回传 | 假模型/假工具的集成测试 |
| 模型输出达到限制 | 保留部分结果，显示真实结束原因，不伪装正常完成 | 提供方响应夹具 |
| 授权请求过期或重复回复 | 已解决请求不会再次执行 | 状态机测试 |
| 用户取消与工具完成同时到达 | 最终状态一致，保留实际副作用记录 | 控制时序的竞态测试 |
| 工具输出远超界面速度 | 缓冲有界，显示和存储策略明确 | 输出压力回放 |
| 输出被截断 | 明确说明截断，保留产物或已采用的限制信息 | 工具输出边界测试 |
| Runner 崩溃 | 下次连接看到中断或未知状态，不盲目重跑 | 故障注入 |
| UI 断开再连接 | 按游标补齐已持久化事件，不重复显示 | 本地连接集成测试 |
| 用户切换会话 | 新事件按会话身份落位，当前输入不丢失 | UI 回放与人工检查 |
| 工具派生子进程 | 取消/超时按约定结束执行范围并回收资源 | 受控子进程测试 |
| 模型用量尚未知 | 显示未知或暂估状态，不记录为确定零成本 | 记录层测试 |
| 应用闲置 | 没有无意义的持续轮询或高频重绘 | Instruments 与进程观察 |

## 7. 当前实施范围与暂缓能力

本轮用 GPUI 创建 Rust 应用，布局、绘制、窗口与 Metal 接入由框架提供。可立即读源码、改应用；暂缓的是从零自研绘制框架。

可直接沿 GPUI 学所有权、状态、事件与子进程，或用 Rust 实现 Harness；是否统一产品语言，等接入与维护体验足够具体再定。

| 暂缓项 | 重新评估的具体触发条件 |
|---|---|
| 从零自研 GPU UI 框架 | 学习目标进一步转向渲染引擎，或现成框架有明确无法满足的需求；不限制现在使用 GPUI |
| 最终整套产品统一语言 | 通过几条实际调用路径了解语言和桥接成本后决定；Rust Harness 可以先独立尝试 |
| CRDT | 多设备确实需要离线同时编辑同一文本并合并 |
| Wasm 插件平台 | 有实际第三方、不可信代码需要能力受控的执行环境 |
| 通用插件市场 | 工具契约已稳定且存在外部开发者需求 |
| 完整终端模拟器/IDE | 用户任务需要持续交互终端或深度代码编辑，现有视图不足 |
| 多 Agent 编排 | 单 Agent 的实际任务存在可测量、可分解的收益 |
| MCP 与 ACP | 分别出现具体工具服务器或外部 Agent/客户端兼容需求 |
| 多设备任务迁移 | 重连同一执行主机无法满足实际需求，且可定义副作用与文件迁移语义 |

首版先保证边界、状态和验证；新增机制需对应真实问题。
